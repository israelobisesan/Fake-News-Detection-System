# AI-Based Fake News Detection System for Social Media

A web application that classifies a news article as **Likely Fake** or **Likely Genuine**
using TF-IDF features and supervised machine learning.

The classifier is a real model, trained and evaluated from the ISOT Fake News Dataset.
Every number in this README was produced by `training/train.py` and is stored in
`models/model_metadata.json`. Nothing is hard-coded.

---

## 1. Project overview

The system takes a headline and an article body, cleans the text, converts it to
TF-IDF features and classifies it with the best-performing of three models.

```
title + " " + article text
        |
        v
[ preprocessing ]  lowercase -> strip publisher markers -> remove punctuation
        |            and numbers -> tokenise -> remove stop words -> lemmatise
        v
[ TF-IDF vectoriser ]   fitted on the TRAINING data only, then saved to disk
        |
        v
[ best classifier ]      Naive Bayes / calibrated Linear SVM / Random Forest
        |
        v
"Likely Fake" or "Likely Genuine"  +  Confidence: XX.XX%
```

Confidence comes from the model's own `predict_proba` output. It is the model's
confidence in its classification, **not** the probability that the article is true.

---

## 2. Features

- Trained and compared **Multinomial Naive Bayes**, **calibrated Linear SVM** and **Random Forest**
- Strict 70 / 15 / 15 stratified split with a fixed `random_state`
- One shared preprocessing implementation used by **both** training and the web app
- Publisher/source markers removed so the score reflects writing style, not provenance
- Real confidence values from calibrated probabilities
- Friendly error handling - no Python tracebacks ever reach the browser
- Escaped output, request size limits, no database and no API keys required

Actual size of the copy used here (slightly different from figures often quoted
online, which say 44,919):

| | Records |
|---|---|
| `Fake.csv` | 23,481 |
| `True.csv` | 21,417 |
| **Total read** | **44,898** |

Columns: `title`, `text`, `subject`, `date`. Files are UTF-8 with CRLF line endings
and quoted multi-line article bodies.

Genuine articles are Reuters wire copy; fake articles come from a set of unreliable
outlets flagged by fact-checkers. Most articles are US political and world news from
2016-2017.

## 8. Training the models

One-time NLTK setup (downloads ~10 MB of corpora; run once):

```powershell
python training/prepare_nltk.py
```

Then train:

```powershell
python training/train.py
```

This takes roughly 3-5 minutes on 4 cores. It runs the **entire experiment twice**:

| Experiment | Publisher markers |
|---|---|
| `naive_baseline` | kept in |
| `de_leaked` | removed - **this is the model that gets deployed** |

Both runs share one identical split, so the comparison is fair.

Preprocessing steps, in order:

1. lowercase
2. strip source artifacts (Reuters datelines, outlet names, URLs, handles, web boilerplate)
3. strip accents, punctuation and special characters
4. remove numbers
5. tokenise
6. remove stop words (NLTK, 198 English words)
7. lemmatise to word roots (WordNet)

If the NLTK corpora are missing the project still runs, falling back to a built-in
stop-word list and skipping lemmatisation, and logs a warning.

## 9. How the models are compared

All three models see identical TF-IDF matrices built from identical splits.

| Model | Configuration |
|---|---|
| Multinomial Naive Bayes | `alpha=0.1` |
| Calibrated Linear SVM | `LinearSVC(C=1.0)` inside `CalibratedClassifierCV(cv=5, method="sigmoid")` |
| Random Forest | `n_estimators=100`, `max_features="sqrt"`, `min_samples_leaf=2`, `n_jobs=-1` |

TF-IDF: `ngram_range=(1,2)`, `min_df=2`, `max_df=0.90`, `max_features=50000`,
`sublinear_tf=True`. Fitted on training rows only; validation and test are
transform-only, so no vocabulary information leaks.

Hyperparameters were fixed **before** training and not tuned, so the validation set
stays clean for model selection. Precision, recall and F1 are computed for the
**FAKE** class, because missing fake news is the worse error for this application.

LinearSVC has no `predict_proba`. Wrapping it in `CalibratedClassifierCV` fits an
internal cross-validated mapping from the SVM's decision margin onto a probability,
which is what makes a genuine confidence score possible for the SVM.

### Validation results (5,798 articles)

**Naive baseline - publisher markers left in**

| Model | Accuracy | Precision | Recall | F1 |
|---|---|---|---|---|
| Multinomial Naive Bayes | 0.9617 | 0.9504 | 0.9656 | 0.9580 |
| **Calibrated Linear SVM** | **0.9952** | **0.9981** | **0.9912** | **0.9946** |
| Random Forest | 0.9921 | 0.9954 | 0.9870 | 0.9912 |

**De-leaked - publisher markers removed (deployed configuration)**

| Model | Accuracy | Precision | Recall | F1 |
|---|---|---|---|---|
| Multinomial Naive Bayes | 0.9522 | 0.9386 | 0.9569 | 0.9476 |
| **Calibrated Linear SVM** | **0.9895** | **0.9942** | **0.9824** | **0.9883** |
| Random Forest | 0.9724 | 0.9786 | 0.9599 | 0.9692 |

## 10. How the best model is selected

The script picks the model with the highest **validation F1 for the FAKE class**,
using validation accuracy only to break ties. It is decided by the measured result,
not by any assumption:

> **Selected: Calibrated Linear SVM**
> Reason: highest validation F1 for the FAKE class (0.9883, accuracy 0.9895)

Random Forest is competitive on accuracy but its F1 is 0.019 lower, and it produces a
noticeably less extreme confidence distribution. Naive Bayes is clearly weakest - it
assumes token independence, which TF-IDF word features violate.

## 11. Final test results (selected model only)

The test set was untouched until this point. It was never used for tuning or selection.

| Metric | Score |
|---|---|
| Accuracy | 0.9888 |
| Precision | 0.9938 |
| Recall | 0.9813 |
| F1-score | 0.9875 |

Confusion matrix (rows = actual, columns = predicted):

| | predicted FAKE | predicted TRUE |
|---|---|---|
| **actual FAKE** | 2,570 | 49 |
| **actual TRUE** | 16 | 3,164 |

49 fake articles were missed; 16 genuine articles were wrongly flagged.

For comparison, the naive baseline scored 0.9962 accuracy / 0.9958 F1 on the same test
set. **That higher score is not the better model** - it is partly explained by
recognising the publisher rather than the writing. The de-leaked model is deployed
because its score is more defensible.

### Why de-leaking barely changed the score

This is an important and honest finding. Removing publisher markers cost only about
0.6 percentage points, which means most of the dataset's difficulty gap lives
*elsewhere*. Inspecting the features the SVM relies on shows the genuine half is
recognisable by ordinary stylistic patterns - Reuters' formulaic phrasing such as
"told Reuters", "said in a statement", "news conference", and its heavy use of weekday
names in datelines - while the fake half carries sensational vocabulary and named
low-quality outlets.

So ISOT remains an easy benchmark even after cleaning. See *Limitations*.

## 14. Evaluation metrics

| Metric | Meaning here |
|---|---|
| **Accuracy** | Share of all test articles classified correctly |
| **Precision** | Of articles called FAKE, how many really were fake |
| **Recall** | Of genuinely fake articles, how many were caught |
| **F1-score** | Harmonic mean of precision and recall; the selection criterion |
| **Confusion matrix** | Counts of each true/predicted pairing, showing the error types |

Because precision and recall can move in opposite directions, F1 is used to compare
models. Recall is weighted heavily in practice because a missed fake article spreads
further than a false alarm.

---

## 15. Understanding the confidence score

> **Confidence represents the model's confidence in its classification, not the
> probability that the news is objectively true or false.**

If the model reports `Likely Fake - Confidence 94.27%`, it means the classifier assigned
roughly 94% of its probability mass to the FAKE class **given the patterns it learned**.
It does **not** mean there is a 94% chance the article is false, and it is not a
measurement of factual accuracy. The model has no access to ground truth; it only
measures similarity to the text it was trained on.

Two further points worth understanding:

- **Confidence is not reliability across the board.** The model returns high confidence
  on out-of-distribution input. A 25-character nonsense sentence was classified
  `Likely Fake` at 97.19% confidence during testing. Confidence tracks familiarity,
  not truth.
- **The labels say "Likely".** This is a statistical classifier, not a fact-checking
  organisation. It cannot read the article, verify claims or check sources.

## 16. Limitations

1. **Not Nigerian news.** The model is trained only on ISOT, which is US-centric,
   political and from 2016-2017. Nigerian articles can be submitted and will produce a
   prediction, but **performance on Nigerian news is not established and must not be
   claimed.** Doing so would require Nigerian-specific labelled data, trained on and
   evaluated on.
2. **Text only.** No images, video, URL reputation, metadata or network analysis. The
   system cannot detect misinformation that is factually accurate but misleading.
3. **Dataset artefacts remain.** Even after removing publisher markers, ISOT's genuine
   half is homogeneous Reuters copy and its fake half comes from a handful of unreliable
   outlets. The high scores partly reflect that, so 0.9888 test accuracy should **not**
   be read as real-world performance.
4. **No hyperparameter tuning.** Fixed a-priori settings were used, so this is not the
   best achievable score. Tuning on the validation set would also have made validation
   less trustworthy, so it was deliberately skipped.
5. **English only.** No multilingual support.
6. **Out-of-distribution input.** Short, non-news or non-English text still produces a
   confident answer, which is misleading.
7. **Static model.** Retraining is required to reflect changes in news language; there
   is no concept of concept drift.
8. **Not a fact-checker.** It does not verify claims, trace sources or replace human
   review.

## 18. Troubleshooting

| Symptom | Fix |
|---|---|
| `ModuleNotFoundError: nltk` | `pip install -r requirements.txt` |
| `Missing trained model` | `python training/train.py` |
| `ModelNotReadyError ... could not be loaded` | Model saved by a different library version - retrain |
| `Resource 'wordnet' not found` | `python training/prepare_nltk.py` - see note below |
| `Preprocessing configuration differs...` warning | NLTK corpora were missing at run time; run `prepare_nltk.py` and restart |
| Port 5000 already in use | `$env:FLASK_PORT="5001"` |
| `Dataset folder not found` | Create `dataset/` and add both CSVs |

### Note: `Resource 'wordnet' not found`

This is a known NLTK quirk on Windows: `nltk.download("wordnet")` can report success
while leaving the archive downloaded but **un-extracted**. The `.zip` is on disk but the
directory NLTK actually reads never appears, so the resource still raises `LookupError`.

`training/prepare_nltk.py` detects that state and unzips the archive itself, printing
`[fixed] wordnet was downloaded but not extracted`. It also verifies both resources by
actually using them before reporting success, rather than only checking that a path exists.

If it cannot repair the problem, the script prints the manual commands:

```powershell
Remove-Item "$env:APPDATA\nltk_data\corpora\wordnet.zip" -ErrorAction SilentlyContinue
python training/prepare_nltk.py
```

The project still runs without these corpora - it falls back to a built-in stop-word list
and skips lemmatisation. Because that changes the tokens the model sees, the app logs a
warning when inference no longer matches the configuration used for training, so a
degraded setup is never silent.

### Running commands from PowerShell

PowerShell does not execute scripts in the current directory unless you prefix them with
`.\`, but this is only needed for `.ps1` files. For Python scripts always spell out the
interpreter, and give the path relative to wherever you are:

```powershell
python training\prepare_nltk.py     # from the project root
python prepare_nltk.py              # from inside the training\ folder
```

Technical errors are written to the console and the Flask log; users only ever see a
friendly message.

## 19. Deploying to Render (free)

The app can be hosted publicly. Only `render.yaml`, `.python-version` and
`requirements-deploy.txt` exist for this; the model itself is already committed.

### What Render runs

```
Build:  pip install -r requirements-deploy.txt && python training/prepare_nltk.py
Start:  gunicorn --bind 0.0.0.0:$PORT --workers 1 --timeout 120 run:app
```

The build step downloads the two NLTK corpora so the app never downloads anything
while serving a request. It also repairs the case where NLTK fetches WordNet but
fails to unpack it, which would otherwise make the app quietly skip lemmatisation.

### Steps

1. Push the repository to GitHub (done).
2. Sign in at <https://render.com>, then **New → Blueprint**.
3. Connect `israelobisesan/Fake-News-Detection-System` and apply.
4. Wait for the build, then open the `onrender.com` URL it gives you.

Render reads `render.yaml` and fills in the build command, start command, health
check and the `FLASK_SECRET_KEY` (generated automatically as a 256-bit value).

### Why one worker

Each gunicorn worker holds roughly **277 MB** once scikit-learn, scipy, pandas,
NLTK and the model are loaded. Render's free tier provides **512 MB**, so a second
worker would exceed the limit and be killed for memory. Raise `--workers` only after
moving to a larger instance.

### What to expect from the free tier

| | |
|---|---|
| Compute | 0.1 CPU, 512 MB |
| Sleeps after | 15 minutes without traffic |
| Cold start | 30-60 seconds to wake, plus ~4 s to load the model |
| Storage | Ephemeral - nothing persists, which is fine as the app stores no user data |
| Card | Not required |
| Always-on alternative | Render Starter, $7/month |

**The cold start matters.** If you open the link during a demo after the app has
been idle, the first page load will appear to hang for up to a minute. Hit
`/health` yourself a minute beforehand to wake it.

### Deploying by hand instead

Ignore `render.yaml` and use **New → Web Service**. Copy the Build and Start
commands above, and set two environment variables in the dashboard:

| Variable | Value |
|---|---|
| `FLASK_SECRET_KEY` | any long random string |
| `FLASK_DEBUG` | `0` |

Keep `requirements.txt` for local Windows work and `requirements-deploy.txt` for
the server. gunicorn only runs on Linux, so it lives in the deployment file only.

### Other platforms

`requirements-deploy.txt` and the gunicorn start command also work on Railway and
Fly.io. For anything else, run gunicorn directly on a Linux host:

```bash
pip install -r requirements-deploy.txt
python training/prepare_nltk.py
export FLASK_SECRET_KEY="$(python -c 'import secrets; print(secrets.token_hex(32))')"
gunicorn --bind 0.0.0.0:8000 --workers 1 run:app
```

Put nginx or Caddy in front for TLS. The app needs no database, no writable
directory and no external API keys.

### Health check

`GET /health` returns the loaded model and its measured test accuracy, and returns
HTTP 503 if the model artifacts are missing:

```json
{"labels":["FAKE","TRUE"],"model":"Calibrated Linear SVM","status":"ok","test_accuracy":0.988791170891533}
```
